# Quy trình i18n

Dự án dùng **i18next** + **react-i18next**. Toàn bộ chuỗi hiển thị được tách
khỏi code, gom vào JSON, và lookup tại runtime qua `t('…')`.

Có **hai cấp namespace** song song:

| Namespace                      | Phạm vi                                      | File JSON                                 | Strict TS typing                    | Hook tại callsite        |
| ------------------------------ | -------------------------------------------- | ----------------------------------------- | ----------------------------------- | ------------------------ |
| `translation` (base)           | Dùng chung mọi tenant - phần cốt lõi của app | `src/lib/i18n/locales/{en,vi}.json`       | **Có** (`ParseKeys<'translation'>`) | `useTranslation()`       |
| Tenant ns (ví dụ `hoaTheoMua`) | Override + thêm cho 1 tenant cụ thể          | `src/tenants/<slug>/locales/{en,vi}.json` | **Không** (key kiểu `string`)       | `useTenantTranslation()` |

Đọc hai phần [Base i18n](#base-i18n) và [Multi-tenant i18n](#multi-tenant-i18n)
là đủ cho công việc hàng ngày. Các phần còn lại là tham chiếu khi cần đào sâu.

---

## Base i18n

### Source files

- `src/lib/i18n/locales/en.json` - primary, là source of truth của mọi key.
- `src/lib/i18n/locales/vi.json` - bản dịch tiếng Việt.
- `src/lib/i18n/i18n.ts` - khởi tạo i18next: nạp base làm namespace
  `translation`, set `defaultNS` và `fallbackNS` cùng là `translation` (việc
  này quan trọng vì tenant ns dựa vào fallback để rớt ngược về base khi
  thiếu key).

### Strict typing

- `.i18n-types/resources.d.ts` được sinh tự động từ `en.json` bởi
  `i18next-cli`. **Không sửa tay** - chạy `yarn i18n:types` mỗi khi `en.json`
  đổi.
- `.i18n-types/i18next.d.ts` sửa tay (rất ngắn), remap shape mà `i18next-cli`
  sinh ra (`{ en: {...} }`) sang namespace runtime đang dùng (`translation`).
- Cả hai `.d.ts` này được kéo vào TS program qua `tsconfig.app.json` với
  pattern `".i18n-types/**/*.d.ts"` (TS bỏ qua thư mục bắt đầu bằng dấu chấm
  trừ khi khai báo explicit).
- `src/lib/i18n/types.ts` export `type I18nKey = ParseKeys<'translation'>`.
  Dùng `I18nKey` mỗi khi bạn lưu translation key trong một typed value
  (field của interface, value của `Record`, phần tử của array...).

### Workflow hàng ngày

**1. Dùng key có sẵn**

```tsx
import { useTranslation } from 'react-i18next'

function Greeting() {
  const { t } = useTranslation()
  return <p>{t('expertNetwork.viewProfile')}</p>
  //          ^ editor sẽ autocomplete từ union key thật
}
```

**2. Thêm key mới**

```tsx
t('myFeature.newAction') // TS sẽ báo lỗi vì key chưa có trong en.json
```

```bash
yarn i18n:extract && yarn i18n:types
```

Sau đó mở `vi.json`, tìm key mới (giá trị rỗng), điền bản dịch. Nếu editor
chưa nhận key mới: **Restart TS Server** (VS Code: ⇧⌘P → "TypeScript:
Restart TS Server").

**3. Lưu key trong typed value**

```ts
import type { I18nKey } from '@/lib/i18n/types'

interface NavItem {
  href: string
  titleKey: I18nKey
}

const NAV: NavItem[] = [
  { href: '/dashboard', titleKey: 'pageTitle.dashboard' },
  { href: '/settings', titleKey: 'pageTitle.settings' }
]
```

Việc này **bắt buộc** để [smart unused checker](#smart-unused-checker) nhận
diện được literal là một chỗ tham chiếu hợp lệ; bạn cũng có autocomplete ngay
tại chỗ gán.

**4. Key động (template literal)**

```ts
t(`meeting.status.${status.toLowerCase()}` as I18nKey)
```

Cast `as I18nKey` bắt buộc vì TS không chứng minh được chuỗi runtime nằm
trong literal union. Smart checker nhận biết prefix `meeting.status.` và coi
mọi key dưới `meeting.status.*` là đã dùng.

## Multi-tenant i18n

Mỗi tenant (org) có thể:

- **Override** key của base (đổi label `account.logout` riêng mà không sửa
  shared component).
- **Thêm** key riêng cho các trang chỉ thuộc tenant đó (ví dụ các trang dưới
  `/htm/...` của Hoa Theo Mua).

### Kiến trúc runtime

```
useTenantTranslation()
   └── useTranslation([tenantNs, 'translation'])
         │
         ├── tra tenant ns trước  ← override khi trùng key
         └── fallback xuống base  ← nhờ fallbackNS = 'translation'
```

- **Base ns** đăng ký tĩnh trong `i18n.ts` lúc app khởi động.
- **Tenant ns** KHÔNG đăng ký lúc khởi động. Bundle locale load động sau khi
  `useGetMe()` trả về user của tenant đó, qua
  `src/lib/i18n/load-tenant-namespace.ts`.
- User của tenant khác **không tải** bundle của tenant này (Vite tự
  code-split mỗi `() => import(...)` thành chunk riêng).

### Cấu hình tenant

Khai báo trong `src/tenants/<slug>/config.ts`:

```ts
export const hoaTheoMuaConfig: Partial<TenantConfig> = {
  // ... modules, custom, defaultLanding, logoUrl ...
  i18nNamespace: 'hoaTheoMua',
  locales: {
    en: () => import('./locales/en.json'),
    vi: () => import('./locales/vi.json')
  }
}
```

- `i18nNamespace` - tên namespace runtime; cũng là key trong `useTranslation`.
- `locales` - map ngôn ngữ → dynamic-import loader.

### Loader

`src/lib/i18n/load-tenant-namespace.ts`:

- **Idempotent**: cùng `(namespace, language)` chỉ load một lần. Set `loaded`
  - map `inFlight` dedupe các call song song.
- **Fallback ngôn ngữ**: thiếu loader cho `vi-VN` → lùi về `vi` → lùi về `en`.
- **Wiring**: `AuthGuardLayout` (`src/layouts/auth-guard.layout.tsx`) gọi
  loader một lần khi `useTenantConfig()` resolve, và đăng ký
  `i18n.on('languageChanged', ...)` để nạp đúng bundle khi user đổi ngôn ngữ
  giữa session.

### Hook tại callsite

```tsx
import { useTenantTranslation } from '@/lib/i18n/use-tenant-translation'

function OrdersHeader() {
  const { t } = useTenantTranslation()
  return <h1>{t('orders.listComingSoon')}</h1>
  //          ^ runtime tra tenant ns trước, fallback base nếu thiếu
}
```

- User của tenant không khai báo `i18nNamespace` → hook hoạt động giống
  `useTranslation()` thường.
- Trong khoảng rất ngắn từ lúc auth resolve cho tới khi loader xong, key
  tenant-only fallback về base (hoặc raw key nếu base cũng không có).
  `AuthGuardLayout` đã gate render đằng sau loading state của `useGetMe`,
  nên flicker hiếm khi thấy.

### Tenant key cố tình KHÔNG được type

`t` trả về bởi `useTenantTranslation` widen thành `(key: string) => string`.
Lý do:

- `i18next.config.js` đã exclude `src/tenants/**` khỏi `extract`, `lint` và
  `types` generation, nên nguồn type không sinh ra cho tenant.
- Sinh type per-tenant sẽ thêm machinery build chỉ để phục vụ vài chục key
  → không xứng.

Hệ quả thực tế:

- File `src/tenants/<slug>/locales/*.json` maintain **bằng tay** - không
  autocomplete, không TS check ở callsite.
- `yarn i18n:extract`, `yarn i18n:check`, `yarn i18n:lint`, `yarn i18n:types`
  **chỉ chạy trên base**. Tenant JSON nằm ngoài vùng phủ của các lệnh đó.

### Thêm một tenant mới

1. Tạo `src/tenants/<slug>/locales/{en,vi}.json` (object rỗng cũng OK).
2. Thêm `i18nNamespace` + `locales` vào `src/tenants/<slug>/config.ts`.
3. Đăng ký org id của tenant vào `TENANT_CONFIGS`
   (`src/lib/feature-flags/tenants.config.ts`).
4. Component đặc thù dùng `useTenantTranslation()` thay cho `useTranslation()`.

**KHÔNG** cần sửa `src/lib/i18n/i18n.ts` hay `src/lib/i18n/i18next.d.ts` khi
thêm tenant - đây chính là điểm chính của thiết kế dynamic.

### Override một key của base cho tenant

Ví dụ base có `account.logout = "Đăng xuất"`, muốn tenant `hoa-theo-mua`
hiển thị "Đăng xuất khỏi cửa hàng" khi đang ở tiếng Việt:

1. Mở `src/tenants/hoa-theo-mua/locales/vi.json`.
2. Thêm key đúng path:
   ```json
   { "account": { "logout": "Đăng xuất khỏi cửa hàng" } }
   ```
3. Component dùng `useTenantTranslation()` tự lấy override.
4. Component dùng `useTranslation()` thuần vẫn lấy bản base.

→ Muốn override "thấm" được vào shared component, shared component phải
migrate sang `useTenantTranslation`. Hiện tại chỉ các component dưới
`src/tenants/**` dùng hook mới; rollout dần tuỳ nhu cầu rebrand.

## Tất cả lệnh i18n (chi tiết)

Toàn bộ script nằm trong `package.json`. **Mọi lệnh dưới đây chỉ tác động
lên base locales** (`src/lib/i18n/locales/*`). Tenant JSON nằm ngoài vùng
phủ.

### `yarn i18n:extract`

> `i18next-cli extract`

Quét `.ts` / `.tsx` trong `src/` (trừ `src/tenants/**`), tìm các lời gọi
`t('…')`, rồi:

- Thêm key mới vào `en.json` (giữ cấu trúc lồng theo dấu chấm).
- Thêm key mới vào `vi.json` với giá trị rỗng.

**Khi nào dùng**: ngay sau khi viết `t('myFeature.newKey')` mà key chưa có
trong JSON.

**Lưu ý**: lệnh này **ghi đè JSON** - đừng chạy nếu đang có thay đổi JSON
dở. Sau `extract`, **luôn** chạy `yarn i18n:types`:

```bash
yarn i18n:extract && yarn i18n:types
```

### `yarn i18n:extract:check`

> `i18next-cli extract --dry-run --ci --quiet`

Giống `extract` nhưng **không ghi gì**. Exit non-zero nếu có key mới trong
code mà chưa có trong JSON. Dùng làm CI gate; được gọi trong `i18n:verify`.

### `yarn i18n:status`

> `i18next-cli status`

In tổng số key trong primary locale (`en`), số namespace, phần trăm hoàn
thành dịch của mỗi locale (ví dụ `vi: 100% (1406/1406)`).

### `yarn i18n:types`

> `i18next-cli types --quiet`

Regenerate `.i18n-types/resources.d.ts` từ `en.json`. Đây là nguồn của
`I18nKey` union - sau khi regenerate, TS biết về key mới (và bỏ key cũ).
File output có comment "Do not edit manually" - luôn dùng lệnh này, đừng
sửa tay.

### `yarn i18n:lint`

> `i18next-cli lint --quiet`

Lint nội dung JSON - bắt:

- Param `{{name}}` ở `en.json` nhưng thiếu/khác trong `vi.json`.
- Tag HTML không khớp (`<0>`, `<1>` mismatched).
- Key trùng tên ở các tầng khác nhau.

Khác `eslint-plugin-i18next` thế nào: `eslint-plugin-i18next` lint **code
TS/TSX**, còn `i18n:lint` lint **JSON**. Hai phạm vi khác nhau.

### `yarn i18n:check`

> `i18n-check --locales src/lib/i18n/locales --source en --format i18next --unused src --only missingKeys invalidKeys undefined --reporter summary`

Dùng `@lingual/i18n-check` để báo 3 loại lỗi:

1. **missingKeys** - key có trong `en.json` nhưng thiếu trong `vi.json`.
2. **invalidKeys** - translation sai format (thiếu/dư `{{var}}` so với gốc).
3. **undefined** - `t('…')` trong code dùng key không tồn tại trong JSON.

Không bao gồm "unused" - chuyển sang [`yarn i18n:unused`](#yarn-i18nunused).

### `yarn i18n:unused`

> `node scripts/i18n-find-unused.mjs`

Report các key trong `en.json` không có chỗ nào trong `src/` tham chiếu.
Custom script (~70 dòng) thay thế `@lingual/i18n-check --only unused` vốn
nhiều false positive với codebase này. Chi tiết kỹ thuật ở
[Smart unused checker](#smart-unused-checker).

Output: tổng số key, tổng số file scan, số template prefix phát hiện, danh
sách key unused. Exit 1 nếu có key unused, 0 nếu không.

### `yarn i18n:unused:fix`

> `node scripts/i18n-find-unused.mjs --fix`

Giống `i18n:unused` nhưng **thật sự xoá** các key unused khỏi **tất cả**
file trong `src/lib/i18n/locales/*.json`. Object con trở thành rỗng cũng bị
xoá luôn (prune cascade).

```bash
git status                  # working tree sạch
yarn i18n:unused            # review danh sách
yarn i18n:unused:fix        # xoá nếu OK
yarn check                  # verify
```

### `yarn i18n:verify`

> `yarn run i18n:extract:check && yarn run i18n:status && yarn run i18n:check && yarn run i18n:lint && yarn run i18n:types`

Chạy tất cả check i18n theo thứ tự:

1. `extract:check` - fail nếu có key trong code chưa extract.
2. `status` - in báo cáo coverage.
3. `check` - fail nếu có missing/invalid/undefined.
4. `lint` - fail nếu JSON sai format.
5. `types` - regenerate types nếu cũ.

`i18n:unused` **không** nằm trong chain - xem [Git hooks](#git-hooks).

### `yarn check`

> `yarn run lint && yarn run i18n:verify && tsc -b`

Gate tổng thể:

1. `lint` - ESLint toàn project.
2. `i18n:verify` - toàn bộ check i18n.
3. `tsc -b` - strict TypeScript check.

Chạy trước khi mở PR; cũng được gọi tự động trong `.husky/pre-push`.

## Commit và push

- **`git commit`** → `.husky/pre-commit` chạy `yarn lint-staged` (ESLint
  `--fix` + Prettier chỉ trên file staged).
- **`git push`** → `.husky/pre-push` chạy `yarn check` (lint + i18n:verify
  - tsc).

Nếu `yarn check` pass ở máy, push sẽ thành công.

## Dọn dẹp định kỳ (thủ công)

```bash
yarn i18n:unused           # report key dead
yarn i18n:unused:fix       # xoá khỏi tất cả file locale
```

Chỉ chạy khi cần - không bắt buộc trên mỗi PR.

## Smart unused checker

### Vì sao cần custom

`@lingual/i18n-check --only unused` chỉ nhận biết literal string truyền
**trực tiếp** vào `t(...)`. Trong codebase này có 3 pattern phổ biến nó
**không thấy**, dẫn đến false positive rất cao (505 unused vs. thực tế 0):

1. **Indirect literal** - key lưu trong typed value
   (`Record<…, I18nKey>`, `I18nKey[]`, literal cast `as I18nKey`), rồi
   forward vào `t()` ở nơi khác.
   ```ts
   const STATUS_LABEL: Record<Status, I18nKey> = {
     pending: 'order.status.pending' // checker thấy là literal chuỗi → OK
   }
   ```
2. **Template literal call** - key có phần động:
   ```ts
   t(`meeting.status.${status.toLowerCase()}` as I18nKey)
   ```
3. **i18next plural suffix** - gọi `t('foo.count', { count })` runtime tự
   resolve sang `foo.count_one` / `foo.count_other`. Trong code chỉ có
   `foo.count`, built-in tưởng `_one`/`_other` là dead.

### Cách smart checker xử lý

`scripts/i18n-find-unused.mjs` (~70 dòng):

- Key trong `en.json` có **đường dẫn đầy đủ** xuất hiện như string literal
  (trong `'...'`, `"..."`, hoặc `` `...` ``) ở **bất kỳ** chỗ nào trong
  `src/` → coi là **đã dùng**.
- Key có **prefix** trùng với static prefix của template literal (matched
  bởi regex `` `[A-Za-z_][\w.]*${ ``) → coi là **đã dùng**.
- Plural suffix (`_zero`, `_one`, `_two`, `_few`, `_many`, `_other`): cắt
  bỏ suffix, kiểm tra stem.

### Triết lý

Smart checker cố tình **thiên về giữ lại** thay vì xoá. False positive
(giữ key đã dead) chỉ tốn vài byte JSON; false negative (xoá key đang
dùng) làm vỡ app runtime. Đánh đổi này chấp nhận được vì strict typing
của `t()` đã chặn dead key mới len lỏi vào.

## Git hooks

| Hook                | Lệnh               | Vì sao                                                                                                               |
| ------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `.husky/pre-commit` | `yarn lint-staged` | Format + lint fix chỉ trên file staged - nhanh, không cản trở commit.                                                |
| `.husky/pre-push`   | `yarn check`       | Gate toàn project (lint + i18n:verify + tsc). Đủ chậm để không nên chạy per-commit, đủ nhanh để chạy trước khi push. |

`yarn i18n:unused` **cố tình không** wire vào `yarn check`. Lý do: có
workflow hợp lệ kiểu "JSON-first" (key thêm vào JSON ở PR này, chỗ gọi mới
có ở PR sau). Nếu wire vào `check`, PR như vậy sẽ bị chặn push. Vì vậy
`i18n:unused` giữ là tool dọn dẹp **thủ công**.

## Khắc phục sự cố (Troubleshooting)

### Gõ `t('…')` mà editor không gợi ý gì (base)

1. Restart TS Server (VS Code: ⇧⌘P → "TypeScript: Restart TS Server").
2. Kiểm tra `tsconfig.app.json` còn `".i18n-types/**/*.d.ts"` trong
   `include` không. Thiếu pattern này thì TS bỏ qua augmentation (mặc định
   TS loại thư mục bắt đầu bằng dấu chấm).
3. Kiểm tra `.i18n-types/i18next.d.ts` còn khai báo `defaultNS: 'translation'`
   và `resources: { translation: Resources['en'] }` không. File này được
   sửa tay - không xoá, không regenerate.
4. Xác minh nhanh: viết `t('definitely.not.a.real.key')` ở file `.tsx` bất
   kỳ. Strict typing đang hoạt động sẽ báo TS2345 kèm danh sách key hợp lệ.
   Compile im lặng → augmentation không được load.

### Gõ `t('…')` trong `src/tenants/**` không gợi ý gì

**Đây là chủ định, không phải lỗi.** Tenant key không có TS types (lý do ở
[Tenant key cố tình KHÔNG được type](#tenant-key-cố-tình-không-được-type)).
Tự kiểm tra key có khớp file JSON không, hoặc grep:

```bash
rg 'key.cần.tìm' src/tenants/<slug>/locales/
```

### `tsc -b` fail ngay sau khi thêm key base mới

Types **không tự** regenerate. Sau `yarn i18n:extract`, **luôn** chạy thêm
`yarn i18n:types` (hoặc `yarn i18n:verify` - bao gồm cả hai).

### Tenant render ra raw key (ví dụ thấy `"orders.listComingSoon"` trên màn hình)

Một trong các nguyên nhân:

1. Key chưa có trong `src/tenants/<slug>/locales/<lng>.json`. Thêm tay.
2. Component đang dùng `useTranslation()` thuần - phải đổi sang
   `useTenantTranslation()` để lookup ở tenant ns.
3. `useGetMe()` chưa resolve nên loader chưa chạy. Hiếm - kiểm tra
   `AuthGuardLayout` đã wrap route hay chưa.
4. `i18nNamespace` chưa khai báo trong `src/tenants/<slug>/config.ts`, hoặc
   slug không khớp.

### Override tenant không "thấm" được vào shared component

Shared component đang dùng `useTranslation()` thay vì
`useTenantTranslation()`. Migrate component sang hook tenant để layered
lookup chạy.

### Key có vẻ unused mà smart checker vẫn giữ

Có khả năng key đang là string value trong typed object/array, hoặc rơi
vào template-literal prefix. Smart checker cố tình permissive. Nếu chắc
chắn dead, xoá thủ công khỏi cả `en.json` và `vi.json`.

### Trang hiển thị literal chuỗi key của base (ví dụ `"foo.bar"`)

Key đang thiếu trong `en.json`. Chạy `yarn i18n:check` confirm, rồi
`yarn i18n:extract` thêm key (hoặc viết tay), sau đó `yarn i18n:types` và
dịch tiếng Việt trong `vi.json`.

### `yarn i18n:check:unused` đâu rồi?

Đã xoá. Là wrapper quanh `@lingual/i18n-check --only unused` - quá nhiều
false positive (505 vs. 0 so với smart checker) và nguy hiểm nếu ai đó tin
output mà xoá thật. Mọi use case unused giờ qua `yarn i18n:unused`.
