# Quy trình i18n

Dự án dùng **i18next** + **react-i18next** kèm strict TypeScript typing. Nhờ vậy
`t('…')` tự động gợi ý (autocomplete) từ đúng danh sách key trong
`src/lib/i18n/locales/en.json`, và TS sẽ báo lỗi khi bạn gõ một key không tồn tại.

## Kiến trúc tổng quan

- **Nguồn dữ liệu (source of truth)**: `src/lib/i18n/locales/en.json` (tiếng
  Anh) và `vi.json` (tiếng Việt). Cả hai được nạp dưới namespace mặc định
  `translation` trong `src/lib/i18n/i18n.ts`.
- **Type augmentation**:
  - `.i18n-types/resources.d.ts` được sinh tự động từ `en.json` bởi
    `i18next-cli`. **Không sửa tay file này** — chạy `yarn i18n:types` mỗi
    khi `en.json` đổi.
  - `.i18n-types/i18next.d.ts` được sửa tay (rất ngắn), nhiệm vụ là remap
    shape mà `i18next-cli` sinh ra (`{ en: {...} }`) sang namespace thật mà
    runtime đang dùng (`translation`).
  - Cả hai file `.d.ts` này được kéo vào TS program qua `tsconfig.app.json`
    với pattern `".i18n-types/**/*.d.ts"` (TS bỏ qua thư mục bắt đầu bằng dấu
    chấm nếu không khai báo explicit).
- **Strict key type**: `src/lib/i18n/types.ts` export
  `type I18nKey = ParseKeys<'translation'>`. Dùng `I18nKey` ở bất kỳ chỗ nào
  bạn lưu translation key trong một typed value (field của interface, value
  trong record, phần tử trong array, v.v.).

## Tất cả lệnh i18n (chi tiết)

Toàn bộ script i18n nằm trong `package.json`. Phần dưới giải thích từng lệnh
một cách độc lập — biết khi nào dùng, output ra sao, cần lưu ý gì.

### `yarn i18n:extract`

> `i18next-cli extract`

**Tác dụng**: quét tất cả file `.ts` / `.tsx` trong `src/`, tìm các lời gọi
`t('…')`, rồi:

- Thêm key mới vào `src/lib/i18n/locales/en.json` (giữ nguyên cấu trúc lồng
  nhau theo dấu chấm).
- Thêm key mới vào `src/lib/i18n/locales/vi.json` với giá trị rỗng (để bạn
  vào dịch sau).

**Khi nào dùng**: ngay sau khi bạn viết một `t('myFeature.newKey')` mới
trong code mà key đó chưa có trong JSON.

**Lưu ý**:

- Lệnh này **ghi đè JSON** — đừng chạy nếu bạn có thay đổi JSON đang dở.
- Sau `extract`, **luôn** chạy `yarn i18n:types` để TS biết về key mới.

```bash
yarn i18n:extract && yarn i18n:types
```

### `yarn i18n:extract:check`

> `i18next-cli extract --dry-run --ci --quiet`

**Tác dụng**: giống `i18n:extract` nhưng **không ghi gì cả**. Nếu có key mới
trong code mà chưa có trong JSON, lệnh exit non-zero.

**Khi nào dùng**: dùng làm CI gate. Mục đích đảm bảo dev đã chạy `extract`
trước khi push. Được gọi tự động trong `i18n:verify`.

### `yarn i18n:status`

> `i18next-cli status`

**Tác dụng**: in ra thông tin tổng quan:

- Tổng số key trong primary locale (`en`).
- Số namespace.
- Phần trăm hoàn thành dịch của mỗi locale (ví dụ `vi: 100% (1406/1406)`).

**Khi nào dùng**: muốn biết `vi.json` còn thiếu bao nhiêu translation.

### `yarn i18n:types`

> `i18next-cli types --quiet`

**Tác dụng**: regenerate `.i18n-types/resources.d.ts` từ `en.json`. File này
là nguồn của `I18nKey` union — sau khi regenerate, TS sẽ biết về key mới (xoá
key cũ).

**Khi nào dùng**: ngay sau `i18n:extract`, hoặc bất cứ khi nào bạn sửa
`en.json` bằng tay.

**Lưu ý**: file đầu ra có comment "Do not edit manually" — luôn dùng lệnh
này, đừng sửa tay.

### `yarn i18n:lint`

> `i18next-cli lint --quiet`

**Tác dụng**: lint nội dung JSON, bắt các lỗi như:

- Param `{{name}}` ở `en.json` nhưng thiếu/khác trong `vi.json`.
- Tag HTML không hợp lệ (`<0>`, `<1>` mismatched).
- Key trùng tên ở các tầng khác nhau.

**Khác `eslint-plugin-i18next` ra sao**: `eslint-plugin-i18next` lint **code
TS/TSX**, còn `i18n:lint` lint **JSON**. Hai phạm vi khác nhau.

### `yarn i18n:check`

> `i18n-check --locales src/lib/i18n/locales --source en --format i18next --unused src --only missingKeys invalidKeys undefined --reporter summary`

**Tác dụng**: dùng `@lingual/i18n-check` để báo 3 loại lỗi:

1. **missingKeys** — key có trong `en.json` nhưng chưa có trong `vi.json`
   (chưa dịch).
2. **invalidKeys** — translation sai format (ví dụ thiếu/dư `{{var}}` so với
   bản gốc).
3. **undefined** — `t('…')` trong code dùng key không tồn tại trong JSON.

**Lưu ý**: lệnh này **không bao gồm "unused"**. Việc kiểm tra unused đã được
chuyển sang `yarn i18n:unused` (smart hơn — xem bên dưới).

### `yarn i18n:unused`

> `node scripts/i18n-find-unused.mjs`

**Tác dụng**: report các key trong `en.json` mà không có chỗ nào trong `src/`
tham chiếu. Đây là custom script (khoảng 70 dòng) thay thế cho
`@lingual/i18n-check --only unused` vốn có quá nhiều false positive với
codebase này.

**Chi tiết kỹ thuật ở mục [Smart unused-key checker](#smart-unused-key-checker) bên dưới.**

**Khi nào dùng**: định kỳ — khi cảm thấy JSON đang "phình ra" và cần dọn dẹp.
Lệnh không tự động chạy trong `yarn check` (xem [Git hooks](#git-hooks)).

**Output**: in tổng số key, tổng số file đã scan, số template prefix phát
hiện được, và danh sách key unused. Exit code 1 nếu có key unused, 0 nếu
không.

### `yarn i18n:unused:fix`

> `node scripts/i18n-find-unused.mjs --fix`

**Tác dụng**: giống `i18n:unused` nhưng **thật sự xoá** các key unused khỏi
**tất cả** file trong `src/lib/i18n/locales/*.json` (en, vi, và bất kỳ
locale nào thêm vào sau này). Nếu một object con trở thành rỗng sau khi xoá,
nó cũng được xoá luôn (prune cascade).

**Khi nào dùng**: chỉ chạy khi đã review output của `i18n:unused` và đồng ý
xoá. Nên commit trước khi chạy để dễ revert.

```bash
git status                  # đảm bảo working tree sạch
yarn i18n:unused            # review danh sách
yarn i18n:unused:fix        # xoá nếu OK
yarn check                  # verify nothing broke
```

### `yarn i18n:verify`

> `yarn run i18n:extract:check && yarn run i18n:status && yarn run i18n:check && yarn run i18n:lint && yarn run i18n:types`

**Tác dụng**: chạy tất cả check i18n read-only theo thứ tự:

1. `extract:check` — fail nếu có key trong code mà chưa extract.
2. `status` — in báo cáo coverage.
3. `check` — fail nếu có missing/invalid/undefined key.
4. `lint` — fail nếu JSON có lỗi format.
5. `types` — regenerate types (nếu types đã cũ).

**Khi nào dùng**: được gọi tự động bởi `yarn check`. Bạn cũng có thể chạy
trực tiếp khi muốn check tất cả mọi thứ trừ TS.

**Lưu ý**: `i18n:unused` **không** nằm trong chain này (xem giải thích ở
[Git hooks](#git-hooks)).

### `yarn check`

> `yarn run lint && yarn run i18n:verify && tsc -b`

**Tác dụng**: gate tổng thể của dự án:

1. `lint` — ESLint trên toàn bộ project.
2. `i18n:verify` — toàn bộ check i18n.
3. `tsc -b` — strict TypeScript check (bao gồm cả union key của `t()`).

**Khi nào dùng**: chạy trước khi mở PR. Cũng chạy tự động trong
`.husky/pre-push`.

## Quy trình hàng ngày

### 1. Dùng một key có sẵn

```tsx
import { useTranslation } from 'react-i18next'

function Greeting() {
  const { t } = useTranslation()
  return <p>{t('expertNetwork.viewProfile')}</p>
  //          ^ editor sẽ autocomplete từ union key thật
}
```

### 2. Thêm key mới

1. Viết lời gọi với tên key bạn muốn (TS sẽ báo lỗi vì key chưa có):

   ```tsx
   t('myFeature.newAction')
   ```

2. Sync JSON và regenerate types:

   ```bash
   yarn i18n:extract && yarn i18n:types
   ```

3. Mở `src/lib/i18n/locales/vi.json`, tìm key mới (giá trị rỗng), điền
   bản dịch tiếng Việt.

4. Nếu editor vẫn chưa nhận key mới: **Restart TS Server**
   (VS Code: ⇧⌘P → "TypeScript: Restart TS Server").

### 3. Lưu key trong một typed value

Khi bạn cần truyền key qua lại (column meta, route handle, lookup map),
hãy khai báo kiểu `I18nKey`:

```ts
import type { I18nKey } from '@/lib/i18n/types'

interface NavItem {
  href: string
  titleKey: I18nKey
}

const NAV: NavItem[] = [
  { href: '/dashboard', titleKey: 'pageTitle.dashboard' },
  { href: '/settings', titleKey: 'pageTitle.settings' }
]
```

Việc này **bắt buộc** để smart unused-key checker nhận diện được literal là
chỗ tham chiếu hợp lệ, và bạn còn có autocomplete ngay tại chỗ gán giá trị.

### 4. Key động (template literal)

Khi suffix của key chỉ biết được lúc runtime:

```ts
t(`meeting.status.${status.toLowerCase()}` as I18nKey)
```

Cast `as I18nKey` là bắt buộc vì TS không thể chứng minh chuỗi runtime là
phần tử của literal union. Smart checker nhận biết static prefix
`meeting.status.` và coi mọi key dưới `meeting.status.*` là đã được dùng.

### 5. Commit và push

- **`git commit`** → `.husky/pre-commit` chạy `yarn lint-staged` (ESLint
  `--fix` + Prettier chỉ trên file đang staged).
- **`git push`** → `.husky/pre-push` chạy `yarn check` (lint + i18n:verify
  - tsc).

Nếu `yarn check` pass ở máy, push sẽ thành công.

### 6. Dọn dẹp định kỳ (thủ công)

```bash
yarn i18n:unused           # report các key dead
yarn i18n:unused:fix       # xoá khỏi tất cả file locale
```

Chỉ chạy khi cảm thấy cần dọn — không bắt buộc trên mỗi PR.

## Smart unused-key checker

### Vì sao cần custom

`@lingual/i18n-check --only unused` chỉ nhận biết literal string truyền
**trực tiếp** vào `t(...)`. Trong codebase này có 3 pattern phổ biến mà nó
**không thấy**, dẫn đến false positive rất cao (kiểm chứng: nó báo 505 key
unused trong khi thực tế là 0 sau khi đã dọn):

1. **Indirect literal** — key được lưu trong một typed value (giá trị của
   `Record<…, I18nKey>`, phần tử của `I18nKey[]`, hoặc literal có cast
   `as I18nKey`), rồi mới forward vào `t()` ở nơi khác.

   ```ts
   const STATUS_LABEL: Record<Status, I18nKey> = {
     pending: 'order.status.pending' // checker thấy là literal chuỗi → OK
   }
   ```

2. **Template-literal call** — key có phần động:

   ```ts
   t(`meeting.status.${status.toLowerCase()}` as I18nKey)
   ```

3. **i18next plural suffix** — gọi `t('foo.count', { count })` thì runtime
   sẽ tự resolve sang `foo.count_one` / `foo.count_other`. Trong code chỉ
   có `foo.count` xuất hiện, nên built-in tưởng `_one`/`_other` là dead.

### Cách smart checker xử lý cả 3 case

`scripts/i18n-find-unused.mjs` (~70 dòng) làm:

- Bất kỳ key nào trong `en.json` có **đường dẫn đầy đủ** xuất hiện như một
  string literal (trong `'...'`, `"..."`, hoặc `` `...` ``) ở **bất kỳ chỗ
  nào** trong `src/` → coi là **đã dùng**.
- Bất kỳ key nào trong `en.json` có **prefix** trùng với một static prefix
  trong template literal (matched bởi regex `` `[A-Za-z_][\w.]*${ ``) →
  coi là **đã dùng**.
- Với plural suffix (`_zero`, `_one`, `_two`, `_few`, `_many`, `_other`):
  cắt bỏ suffix, kiểm tra stem có được tham chiếu không.

### Triết lý

Smart checker cố tình **thiên về giữ lại** thay vì xoá. False positive (giữ
một key thật ra đã dead) chỉ tốn vài byte trong JSON; false negative (xoá
một key đang dùng) sẽ làm vỡ app khi runtime. Đánh đổi này chấp nhận được
vì strict typing của `t()` đã chặn không cho dead key mới len lỏi vào.

## Git hooks

| Hook                | Lệnh               | Vì sao                                                                                                               |
| ------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `.husky/pre-commit` | `yarn lint-staged` | Format + lint fix chỉ trên file đang staged — nhanh, không cản trở commit.                                           |
| `.husky/pre-push`   | `yarn check`       | Gate toàn project (lint + i18n:verify + tsc). Đủ chậm để không nên chạy per-commit, đủ nhanh để chạy trước khi push. |

`yarn i18n:unused` **cố tình không** được wire vào `yarn check`. Lý do: có
những workflow hợp lệ kiểu "JSON-first" (key được thêm vào JSON ở PR này,
chỗ gọi mới có ở PR sau). Nếu wire vào `check`, những PR như vậy sẽ bị
chặn push. Vì vậy `i18n:unused` được giữ là tool dọn dẹp **thủ công** —
chạy khi muốn.

## Khắc phục sự cố (Troubleshooting)

### Gõ `t('…')` mà editor không gợi ý gì

1. Restart TS Server (VS Code: ⇧⌘P → "TypeScript: Restart TS Server").
2. Kiểm tra `tsconfig.app.json` còn `".i18n-types/**/*.d.ts"` trong field
   `include` không. Thiếu pattern này thì TS bỏ qua type augmentation
   (mặc định glob của TS loại các thư mục bắt đầu bằng dấu chấm).
3. Kiểm tra `.i18n-types/i18next.d.ts` còn khai báo
   `defaultNS: 'translation'` và `resources: { translation: Resources['en'] }`
   không. File này **được sửa tay** — không xoá, không regenerate.
4. Để xác minh nhanh, viết `t('definitely.not.a.real.key')` ở một file
   `.tsx` bất kỳ. Nếu strict typing đang hoạt động, TS phải báo lỗi TS2345
   kèm danh sách key hợp lệ. Nếu compile im lặng → augmentation không được
   load.

### `tsc -b` fail ngay sau khi thêm key mới

Types **không tự động** regenerate. Sau `yarn i18n:extract`, **luôn luôn**
chạy thêm `yarn i18n:types` (hoặc chạy luôn `yarn i18n:verify` — nó bao gồm
cả hai bước).

### Một key có vẻ unused mà smart checker vẫn giữ

Khả năng cao là key này đang là string value trong một typed object/array
ở đâu đó, hoặc fall vào một template-literal prefix nào đó. Smart checker
cố tình permissive với prefix match. Nếu bạn chắc chắn dead, xoá thủ công
khỏi cả `en.json` và `vi.json`.

### Trang hiển thị literal chuỗi key (ví dụ `"foo.bar"` hiện trên màn hình)

Key đang thiếu trong `en.json`. Chạy `yarn i18n:check` để confirm, rồi
`yarn i18n:extract` để thêm key (hoặc viết tay vào `en.json`), sau đó
`yarn i18n:types` và dịch tiếng Việt trong `vi.json`.

### `yarn i18n:check:unused` đâu rồi?

Đã xoá. Nó là wrapper quanh `@lingual/i18n-check --only unused` — quá nhiều
false positive (505 vs. 0 so với smart checker) và nguy hiểm nếu ai đó tin
output mà xoá thật. Tất cả use case unused giờ đi qua `yarn i18n:unused`.
